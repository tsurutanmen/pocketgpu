# 参加の約束に入れる項目（下書き・2026-10-10）

文は鶴田さんが書きます。ここには**項目と、なぜ要るかの 1 行**と、**似た試験の約束の例（出典つき）**だけを置きます。
例は主に Apple の Beta Software Agreement（2024-09-09 版）を使いました。条文番号はその PDF のものです。
https://beta.apple.com/agreements/ea1880/apple-beta-software-agreement-ea1880-lyl176-20240909-en.pdf

注意：Apple の約束書は大きな会社が出す英語の契約で、そのまま写すものではありません。「こういう項目を、こういう理由で置いている」という例として読んでください。法律の助言ではありません。

---

## 1. 配り直し禁止

- **なぜ要るか**：まとめには 1 人ずつ印が入っている。ほかの人に渡ると、誰から出たか分からなくなり、印の意味がなくなる。
- **例 1（Apple §1）**：参加者は、Apple から受け取ったソフトなどの物を、書面で認められない限り**共有も譲渡もできない**。参加に使うアカウントとパスワードも、誰とも共有できない。
- **例 2（Apple §3）**：ソフトは試験と評価のためだけに使い、貸す・売る・又貸しする・配る・渡すことをしない。
- 出典：上の PDF の §1 と §3。

## 2. 中を調べるときは、先に許可をもらう

- **鶴田さんの方針（10/10）**：中を調べること自体を全部禁止にはしない。**調べたい・手を加えたいときは、先に鶴田さんに聞いて許可をもらう**。許可なしの分解・解析・まねて作ることはしない。
- **なぜ要るか**：ドライバやアプリを勝手に分解して中身を取り出す、同じ物を作る、といったことを避けたい。一方で、詳しい人が中を見て直しを手伝ってくれる道は残したい。
- **例 1（Apple §3）**：逆コンパイル・リバースエンジニアリング・分解・復号・ソースコードを取り出そうとすることをしない。複製・改変・派生物を作ることもしない（ただし法律が禁じられない範囲と、オープンソースの部分は例外）。
- **例 2（Apple §6）**：得た情報を、自分や第三者の利益のために使わない（書面の承認が要る）。
- 出典：上の PDF の §3 と §6。

## 3. 意見と記録の扱い

- **なぜ要るか**：感想と記録は改良のために使う。何をどこまで集めるか、使い道、個人が特定されないことを先に決めておく。
- **例 1（Apple §4）**：バグ報告・アンケート・要望・問題の報告などを「Feedback」と呼ぶ。契約が別にない限り、Apple は Feedback を**どんな目的にも使える**。
- **例 2（Apple §8.2）**：集める物の種類（診断・技術・使用の記録、機器の識別子、ハードと OS の仕様、性能の数字など）を列挙し、**参加者個人を特定しない形で**集めると書く。位置情報は、位置情報サービスがオンのときだけ。オプトアウトの道もある。
- **例 3（Apple §8.1）**：未成年から集めるときは、親か保護者の同意を取るのは配る側の責任。
- **このキットでの具体**：報告の道具（report.ps1）はユーザー名・PC 名・IP を入れない作りにしてある。約束にも「報告に入る物・入らない物」を書いておくとよい。
- 出典：上の PDF の §4・§8.1・§8.2。

## 4. いつでも止められる

- **なぜ要るか**：試験は善意で受けてもらう。やめたいときに理由を聞かれたり、引き止められたりしないようにしたい。
- **例 1（Apple §14）**：参加者は、**いつでも・理由がなくても**契約や個別の試験をやめられる。ただしやめるときは、受け取ったソフトなどを返すか消す。Apple 側も、いつでも・理由なしに終わらせられる（書面の通知で）。終わったあとも続く項目（§3、§4〜8、§11〜20 など）がある。
- **例 2（Windows Insider Program・二次の情報）**：Insider の登録を外す、または機器を外す、の 2 つのやめ方がある。https://windowsreport.com/?p=734192 （Microsoft の公式の説明は https://learn.microsoft.com/windows-insider/get-started ）
- **このキットでの具体**：やめるときに消す物（ドライバ、dxvk の DLL、iPhone のアプリ、Apple ID の署名）を、手順として書いておくと迷わない。

## 5. iPhone や PC に何か起きたときの扱い

- **なぜ要るか**：試験の物は不具合があり得る。何が起きても配る側が全部は責任を負えないこと、事前にバックアップを取ることを、先に伝える。
- **例 1（Apple §7）**：ソフトにはエラーがあり、**機器やデータの不具合・破損・消失**が起こり得る。機器は元の状態に戻せないことがある。Apple は、参加の前と個別の配布の前に**バックアップを取ることを強く勧める**。本番や業務に重要な機器では使うべきではない。費用や損害は Apple が責任を負わない。
- **例 2（Apple §12・§13）**：「現状のまま」で保証しない。責任の範囲を制限する。
- **このキットでの具体**：無料の Apple ID の署名は 7 日で切れ、入れ直しが要る（Sideloadly の公式ページ）。Apple ID を第三者の道具に入れる点も、前もって伝えておく。AltStore の FAQ は「メールとパスワードは Apple にだけ送られる」と書いている。https://faq.altstore.io/altstore-world/how-to-install-altstore-windows
- 出典（Apple）：上の PDF の §7・§12・§13。

## 6. 未成年

- **なぜ要るか**：高校生を含め、未成年が参加することがあり得る。同意の取り方を決めておく。
- **例 1（Apple §1）**：参加者は、住んでいる地域の**成人の年齢**（多くの国で 18 歳以上）であることを保証する。成人でない利用者がいるときは、その親か保護者の許可を得たことを認める。
- **例 2（Apple §1）**：13 歳から成人までの子どもについては、親か保護者が、**自分の責任と監督のもとで**参加を認められる。子どもの違反は親・保護者の責任になる。
- 出典：上の PDF の §1。
- 注意：日本の成人は 18 歳。ただし、これは Apple の約束書の読みであって、日本の法律の確認はしていません。**[未確認]**

## 7. 配った印のこと

- **なぜ要るか**：まとめには 1 人ずつ印（ドライバの中の 32 文字と、iPhone のアプリの中の印のファイル）を入れてある。外に出たときに誰の分か分かるようにするためで、試す人には先に知らせておく。
- **近い例（Apple §7）**：個別の試験に参加するときは、機器を Apple に登録し、**機器の固有の識別番号**などの必要な情報を渡すことがある、と書いている。人ごと・機器ごとに識別することを、約束の中で先に断っている例。
- **近い例（Apple §1）**：参加に使うアカウントを共有しない。
- **ただし**：「配る物に人ごとの印を入れること」そのものを書いた約束の例は、今回は見つかりませんでした。**[未確認]**
- **このキットでの具体**：印は誰の物かを見分けるために使い、報告や記録とは結びつけない（結びつけるなら、そう書く）。台帳（`tester_kit\ledger.csv`）に何を残すかも、約束に書くと誠実。

## 8. 著作権は鶴田さんにある。手を加えた物も鶴田さんのもの

- **鶴田さんの方針（10/10）**：ドライバ・アプリ・台本などの著作権は鶴田さんにある。試す人が許可をもらって手を加えた物や、それをもとに作った物の著作権も、鶴田さんのものにする。
- **なぜ要るか**：手伝ってもらった直しが、あとで「自分の物だ」と言われて使えなくなったり、別のところで使われたりするのを防ぐ。
- **日本の法律で気をつけること**（法律の助言ではない。本文を決める前に確かめる）
  - 試す人が手を加えた部分の著作権は、まず**手を加えた人に生まれる**。鶴田さんのものにするには、約束に「**譲り渡す**」と書く必要がある。
  - 譲り渡すと書いても、**著作権法 27 条（翻訳・翻案など）と 28 条（二次的著作物の利用）の権利は、特に書かないと譲った中に入らないとみなされる**（著作権法 61 条 2 項）。なので「27 条と 28 条の権利を含めて譲り渡す」と書くのがふつう。
  - **著作者人格権**（名前を出す・勝手に変えられない、など）は人に譲れない（著作権法 59 条）。なので「**著作者人格権を行使しない**」と書くのがふつう。
  - 試す人が**未成年**だと、保護者の同意がない約束はあとで取り消せる（民法 5 条）。6 番の未成年の項目とつなげる。
  - 意見や報告（3 番）も、「自由に使ってよい」と同じところに書いておくと迷わない。
- **例（Apple §3・§4）**：改変や派生物を作らない（§3）。Feedback は Apple がどんな目的にも使える（§4）。

## 9. 手伝ってくれた人の名前を、本番のときに載せる

- **鶴田さんの方針（10/10）**：試してくれた人・直しを手伝ってくれた人の名前を、本番で公開するときに載せる。
- **なぜ要るか**：8 番で著作権を鶴田さんにまとめ、著作者人格権も行使しないと書いてもらう。その代わりに、手伝ってくれたことはこちらから名前で示す。試す人が納得しやすく、手伝う気にもなりやすい。
- **決めておくこと**
  - 載せる名前：本人が選ぶ（本名でなく Reddit や Discord の名前でもよい）
  - 載せない選択：本人が「載せないで」と言えば載せない
  - 載せる場所：アプリの画面・README・サイトなど、どこに載せるか
  - 何をした人を載せるか：**鶴田さんの方針（10/10）＝直しを手伝った人に加えて、試して報告や意見を送ってくれた人も載せる**。キットを受け取っただけで何も送っていない人は載せない
- **8 番との関係**：「著作者人格権を行使しない」と書くと、名前を出してもらう権利も行使しないことになる。なので、名前を載せることは約束の中に**こちらの約束として**書いておくのがよい。

## まだ項目に入っていないが、入れるか決めたいもの

1. **費用**：無料の Apple ID で、7 日ごとに入れ直しが要る。お金はかからない（鶴田さんの方針）が、手間はかかる。先に書いておくと不満が出にくい。（出典：Sideloadly の公式ページ https://sideloadly.io/ ）
2. **Apple ID の扱い**：試す人が自分の Apple ID を第三者の道具に入れる。自己責任であること、使い捨ての ID を使う手があること。（AltStore の FAQ は「Apple にだけ送られる」と書いている。）
3. **公開の範囲**：試験のことをどこまで外に話してよいか。Apple の約束書は「存在そのものも秘密」としているが（§5）、このキットでは話してよいなら、そう書く。
4. **連絡の場所と応答の目安**：Discord か contact@。いつまでに返事をするか。
